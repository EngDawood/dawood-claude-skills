# Project Analyzer Skill

## الهدف
تحليل أي مشروع فريلانس جديد واستخراج كل ما يحتاجه داوود لتقدير العمل والبدء فيه.

## خطوات التحليل

### 1. تحديد نوع المشروع
حدد الفئة أولاً:
- **كود / تطوير**: web, mobile (Flutter), backend, bot, API
- **أكاديمي**: بحث، تقرير، مراجعة أدبيات، دراسة حالة
- **PowerPoint**: عرض تقديمي، محاضرة، دفاع رسالة
- **موقع**: landing page, portfolio, business site
- **هندسة / علوم**: حسابات، رسومات، تقارير تقنية
- **تمريض / صحة**: خطط رعاية، دراسات حالة طبية
- **مختلط**: أكثر من نوع

### 2. استخراج المتطلبات

اقرأ المشروع بعناية واستخرج:

**Deliverables** — ماذا يجب أن يُسلَّم بالضبط؟
- نوع الملف المطلوب (PDF, DOCX, PPTX, code repo, APK...)
- عدد الصفحات / الشرائح / الميزات إن ذُكر
- متطلبات التنسيق (APA, IEEE, RTL, university template...)

**Technical Requirements** (للمشاريع التقنية)
- اللغة / الـ framework المطلوب
- قاعدة البيانات، APIs، خدمات خارجية
- بيئة التشغيل (web, Android, iOS, server...)

**Content Requirements** (للمشاريع الأكاديمية)
- الموضوع والنطاق
- عدد المصادر إن ذُكر
- متطلبات اللغة (عربي، إنجليزي، مختلط)

### 3. تقدير الوقت والجهد

قدّر بناءً على حجم ونوع العمل:

| المستوى | الوصف | التقدير |
|---------|-------|---------|
| صغير | واجب بسيط، صفحتين، كود بسيط | 1-3 ساعات |
| متوسط | بحث 5-10 صفحات، تطبيق بسيط، عرض 15 شريحة | 4-10 ساعات |
| كبير | مشروع متكامل، بحث طويل، تطبيق متعدد الشاشات | 10-30 ساعة |
| ضخم | مشروع تخرج، نظام كامل، رسالة ماجستير | 30+ ساعة |

### 4. تحديد النقاط الغامضة

ابحث عن أي من هذه:
- متطلبات غير واضحة أو متناقضة
- نطاق العمل غير محدد (scope creep خطر)
- معلومات ناقصة (template، بيانات، credentials...)
- deadline غير مذكور
- توقعات قد تكون غير واقعية

## صيغة المخرج

اكتب التحليل بالعربي دائماً، مع ذكر المصطلحات التقنية بالإنجليزي كما هي.

```
## 📋 تحليل المشروع

**النوع:** [نوع المشروع]
**اللغة المطلوبة:** [عربي / إنجليزي / مختلط]

---

### ✅ المطلوب تسليمه (Deliverables)
- [deliverable 1]
- [deliverable 2]
...

### 🔧 المتطلبات التقنية / المحتوى
- [requirement 1]
- [requirement 2]
...

### ⏱️ تقدير الوقت
**المستوى:** [صغير / متوسط / كبير / ضخم]
**التقدير:** [X - Y ساعة]
**السبب:** [جملة قصيرة توضح التقدير]

### ❓ نقاط تحتاج توضيح
- [سؤال 1 للعميل]
- [سؤال 2 للعميل]
...
(اكتب "لا توجد نقاط غامضة" إذا كان كل شيء واضحاً)

### 💡 ملاحظات إضافية
[أي تحذيرات، اقتراحات، أو أشياء يجب الانتباه لها]
```

---

## تعليمات إضافية

- **لا تفترض** — إذا كان هناك غموض، ضعه في "نقاط تحتاج توضيح"
- **كن محدداً** في الـ deliverables، لا تكتف بـ "كود" أو "بحث"
- **التقدير للوقت الفعلي** للشغل، ليس وقت التسليم
- إذا كان المشروع ملف مرفق (PDF, DOCX, صورة) — اقرأه كاملاً أولاً قبل التحليل
- إذا كان الوصف فقط نص — اعتمد عليه مع الإشارة لما ينقص
